# セキュリティポリシー

[English](./SECURITY.md) | 日本語

## サポート対象バージョン

`expo-shelfit` の最新公開バージョンのみがセキュリティ修正の対象です。古いバージョンには修正を適用しないため、報告の前に最新版へ更新してください。

## 脆弱性の報告

セキュリティ上の問題については**公開Issueを作成しないでください**。

GitHub Security Advisoriesを通じて非公開で報告してください:

1. [Securityタブ](https://github.com/my-shelfio/shelfit/security/advisories)に移動
2. **Report a vulnerability** をクリック

7日以内に初回の返信があります。修正がリリースされた後、匿名を希望しない限り、アドバイザリ内でクレジットされます。

## このCLIがアクセストークンをどう扱うか

`expo-shelfit` は単一の認証情報のみを読み取ります: **`EXPO_TOKEN`** 環境変数です。以下は意図的な設計上の制約であり、いずれかへの違反はセキュリティ上の問題として報告してください:

- **トークンが `argv` から読み取られることはありません。** コマンドライン引数は、マシン上の他のすべてのプロセスからプロセス一覧経由で見えてしまいます。
- **トークンがディスクに書き込まれることはありません。** 設定ファイルもキャッシュもログもありません。
- **トークンが出力されることはありません。** 出力・エラーメッセージ・進捗表示のどこにも表示されません。
- **トークンの送信先はただ。1つだけです**: EAS GraphQLエンドポイント（`https://api.expo.dev/graphql`）に、HTTPS経由で、`Authorization` ヘッダーとして送信されます。
- **ランタイム依存関係はゼロです。** 公開されているパッケージにはファーストパーティのコードしか含まれないため、監査すべき推移的なサプライチェーンが存在しません。

> `EXPO_API_URL` でエンドポイントを上書きできます。これはローカルテスト用に存在するもので、意図的にREADMEには記載しておらず、互換性の保証対象外です。信頼できないホストを指定しないでください — そうするとトークンがそのホストに送信されてしまいます。

## 依存関係

`expo-shelfit` は**ランタイム依存関係ゼロ**で提供されています — 公開パッケージ（`bin/`、`src/`）にはファーストパーティのコードしか含まれないため、インストール時に監査すべき推移的なサプライチェーンが存在しません。

開発専用のツール（Vitest、Biome）は `devDependencies` に列挙されており、公開されるtarballには含まれません — `package.json` の `files` と `npm pack --dry-run` で確認できます。Dependabot（`.github/dependabot.yml`）がこれらとCIで使用するGitHub Actionsを最新に保っています。

## CIのシークレット

CIで使用される唯一のシークレットは `EXPO_TOKEN` で、リポジトリのシークレットとして保存され、週次のAPIカナリーワークフロー（`.github/workflows/api-canary.yml`）でのみ、実際のEAS APIに対するスモークテストに使用されます。ログに出力されることはなく（上記「このCLIがアクセストークンをどう扱うか」参照）、フォークからトリガーされたワークフローからは利用できません。

## 対象範囲

対象外: EAS API自体の脆弱性、および攻撃者がすでにCLIの実行環境を制御している必要がある問題（例えば、環境変数を読み取れるマシン）。
